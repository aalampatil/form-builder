## Operational follow-up

The migration account is privileged. Before connecting new tenant request handling, provision a separate restricted application login with the role and transaction boundaries described in the [operations guide](../operations.md). Group roles created by migrations are not login credentials.

Normal application connections still depend on a working DNS resolver for the configured hostname. This run's fallback was temporary and was not installed in application code or system settings. Correct the local resolver if ordinary connection commands continue to fail with `ENOTFOUND`/`EREFUSED`.

Future migration runs should explicitly select the intended environment file. From the repository root, with a working resolver:

```sh
pnpm exec dotenv -e .env.production --no-expand -o -- pnpm --filter @repo/database db:migrate
```

The `-o` option makes the selected file override an already-set shell variable, preventing an unrelated `DATABASE_URL` from silently selecting another database. `--no-expand` preserves literal values rather than interpreting dollar signs in credentials. Continue to review pending migrations and follow the rollout guidance before applying future changes to populated databases.
